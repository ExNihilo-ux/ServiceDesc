# Backend: ServiceDesc Airport Maintenance

Бэкенд системы автоматизированной обработки заявок на обслуживание аэропорта.  
**Стек:** FastAPI + asyncpg + PostgreSQL (pgvector) + Pydantic Settings.

##  Роль в системе

Бэкенд выступает **интеллектуальным маршрутизатором**:
1.  Принимает заявки (текст, фото, геолокация) от мобильного приложения.
2.  Генерирует векторные эмбеддинги описаний неисправностей.
3.  Осуществляет семантический поиск исторических прецедентов через `pgvector`.
4.  Автоматически направляет задачи в профильные отделы на основе классификации ИИ.

## Архитектура приложения

Проект следует строгому разделению ответственности:

| Слой | Папка | Назначение |
| :--- | :--- | :--- |
| **API** | `app/api/v1/` | Роутеры FastAPI, DTO-валидация, HTTP-ответы |
| **Services** | `app/services/` | Бизнес-логика: маршрутизация, вызов LLM, обработка фото |
| **Repositories** | `app/repositories/` | Raw SQL + asyncpg. Никакого ORM. Полный контроль над pgvector |
| **Schemas** | `app/schemas/` | Pydantic модели, кастомные типы (`NullableFloatList`), миксины валидации |
| **Core** | `app/core/` | Конфигурация (`config.py`), управление пулом БД (`database.py`) |
| **SQL** | `sql/migrations/` | Чистые SQL-скрипты схемы БД (SQL-First подход) |

### Ключевые технические решения

-   **Raw SQL вместо ORM:** Необходим для работы с типом `vector`, операторами косинусного сходства `<=>` и кастомными функциями поиска.
-   **Pydantic Settings:** Вся конфигурация (включая `EMBEDDING_DIMENSION`) вынесена в корневой `.env`. Путь вычисляется динамически через `Path(__file__)`.
-   **TDD по слоям:** Unit → Integration → E2E. Каждый слой изолирован и имеет свои фикстуры.
-   **Миксины для валидации:** Логика nullable-полей и проверки размерности вектора вынесена в переиспользуемые миксины, чтобы не дублировать код в DTO.


### 1. Unit-тесты (`tests/unit/`)
Проверяют чистую логику без БД и HTTP.
-   **Что тестируем:** Валидаторы эмбеддингов, утилиты, бизнес-правила сервисов.
-   **Правило:** Обязательно мокаем `settings`. Не зависим от `.env`.
-   **Запуск:** `pytest tests/unit/ -v`

### 2. Integration-тесты (`tests/integration/`)
Проверяют взаимодействие репозиториев с БД.
-   **Что тестируем:** SQL-функции, upsert-логику, векторный поиск, FK-констрейнты.
-   **Правило:** Каждая транзакция обёрнута в `BEGIN...ROLLBACK`. Данные готовятся один раз на класс тестов через `setup_search_data`.
-   **Запуск:** `pytest tests/integration/repositories/ -v`

### 3. E2E-тесты (`tests/e2e/`)
Проверяют полный HTTP-цикл через `AsyncClient`.
-   **Что тестируем:** Валидацию DTO, статус-коды, маппинг ответов, обработку ошибок.
-   **Правило:** Пул БД инициализируется явно в фикстуре `init_db_for_e2e` (lifespan не запускается).
-   **Запуск:** `pytest tests/e2e/ -v`

## Архитектура миграций (SQL-First)

Схема БД описывается чистым SQL. Alembic — только система версионирования и доставки. Это даёт полный контроль над DDL, типами `pgvector` и индексами HNSW.

### Структура папок

| Папка | Назначение |
| :--- | :--- |
| `sql/migrations/` | UP-скрипты (применение изменений схемы) |
| `sql/rollbacks/` | DOWN-скрипты (безопасный откат) |
| `alembic/versions/` | Python-обёртки (runner'ы), генерируются автоматически |
| `scripts/` | Утилита `new_migration.py` для создания тройки файлов |

### Workflow создания миграции

1.  **Создать новую миграцию:**
    ```bash
    python scripts/new_migration.py "add_hnsw_index_to_embeddings"
    ```
    Скрипт создаёт три файла: UP-SQL, DOWN-SQL и Python-runner.

2.  **Написать SQL:**
    Заполни созданные `.sql` файлы кодом между `BEGIN;` и `COMMIT;`.

3.  **Применить:**
    ```bash
    docker compose exec backend alembic upgrade head
    ```

4.  **Откатить (при необходимости):**
    ```bash
    docker compose exec backend alembic downgrade -1
    ```

## ️ Инфраструктура и запуск

-   **Python:** 3.14-slim
-   **DB:** PostgreSQL 16 + pgvector 0.7+
-   **Drivers:** `asyncpg` (runtime), `psycopg2-binary` (Alembic)
-   **Config:** Корневой `.env`, путь резолвится относительно `config.py`
-   **Dev Server:** Uvicorn с `--reload` в Docker Compose
